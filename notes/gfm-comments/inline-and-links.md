# Inline phase, links, and emphasis

The inline phase reads each text block that the block phase reports. It finds the raw HTML spans and every construct that decides whether a `<!--` is raw HTML, and it reports the markup that links, images, and autolinks generate. That markup can close an open attribute value or comment state in the [HTML tokenizer](./html-tokenizer.md). Aligned table cells write markup too, but the block phase reports their alignment and [src/index.ts](../../src/index.ts) writes the opening tags.

## Inline phase

**Inline phase** ([inline/index.ts](../../src/inline/index.ts)). Within each text block, it finds raw HTML spans as `handle_pointy_brace` does. It lexes what decides where raw HTML can start or whether it renders: backslash escapes, code spans, autolinks, and links and images, as `handle_close_bracket` does. A comment in a link destination or title becomes part of the URL or title, and an image's alt text renders as an attribute value, so neither holds a comment. It reports the [markup of links, images, and autolinks](#link-image-and-cell-markup) in order with the raw HTML spans. When the source can contain foreign content, it also tracks generated [emphasis and strikethrough](#generated-emphasis-and-strikethrough) elements. Other text renders escaped and cannot open or close a comment.

## Bare URL autolinks

[inline/bare-autolink.ts](../../src/inline/bare-autolink.ts) ports [`url_match`, `www_match`, `check_domain`, and `autolink_delim`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/autolink.c#L21-L277). URLs match at `:` and `w`, except within an open link or image bracket ([`match`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/autolink.c#L279-L292)). Backticks and backslashes inside a matched URL are link text; `<` ends the URL so a following comment can render. The domain check reads UTF-8 bytes: after a valid non-ASCII character it reaches a continuation byte and stops, while an invalid character stops it immediately. The loop starts at the host's second byte, so a non-ASCII first character, or a NUL that became U+FFFD, ends it at once: `http://é_foo/` is linked because the scan never reaches the `_`. The host's first character uses the renderer's fixed [Unicode space and punctuation table](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/utf8.c#L248-L316), not the JavaScript runtime's Unicode version. Email autolinks are added to already parsed text nodes in [`postprocess_text`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/autolink.c#L321-L460), so they do not affect inline parsing.

Code span scanning also models cmark-gfm's [backtick cache](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/inlines.c#L312-L349). After a search reaches the end, a later successful search can overwrite a cached position, causing a subsequent backtick to remain literal even when another backtick follows it.

## Generated emphasis and strikethrough

Generated end tags can close foreign content. cmark-gfm 0.29.0.gfm.13 renders `*<svg>*` as `<em><svg></em>`. In [GitHub probe 17](./github-oracle.md#github-probes), a following CDATA opener is outside SVG. On 2026-11-15, GitHub also rendered both marker openers after `**<svg>**` and `~~<svg>~~` (fixtures `strong-closes-svg` and `del-closes-svg` in the [probe fixtures](./github-oracle.md#probe-fixtures)). The [foreign content tests](../../tests/specs/rendering/foreign-content.ts) check those updates, an unmatched `*`, and a nested case whose inner `</em>` closes SVG before its outer `</strong>`.

[inline/emphasis.ts](../../src/inline/emphasis.ts) ports cmark-gfm 0.29.0.gfm.13's [delimiter flanking rules](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/inlines.c#L415-L484), [emphasis matching](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/inlines.c#L672-L833), and [strikethrough extension](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/strikethrough.c#L8-L80). It preserves the extension's 100-character scan limit and its removal of unequal tilde pairs without a `del` element. It indexes candidate openers by delimiter character, length modulo 3, and whether they can close. Each closer checks a bounded set of bucket tails instead of repeatedly scanning backward, and intervening delimiters are removed after a match. The inline phase replays generated elements with raw HTML spans and link events in source order, and suppresses a `strong` whose immediate parent is `strong`, as [the renderer](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/html.c#L366-L374) does. It tracks these elements only when the source can contain foreign content.

## Link, image, and cell markup

**Decision (2026-11-16): render the markup of links, images, autolinks, and aligned table cells when it can meet an open attribute value.** Raw HTML can leave an attribute value open, as in `<div title="`. The browser then reads the rendered output that follows as part of the value, and the first quote in generated markup closes it. Before this change, the scanner treated these writes as markup that ends in `>`, so a quoted value stayed open across `<a href="/u">`, and the scanner missed every comment after it. This caused all of the `tables` fuzz mismatches: 31, 31, and 19 on seeds 7, 11, and 23, and 29 on seed 1.

The scanner writes each of these as the renderer writes it, through the tokenizer's `generated` path, which renders only outside the data state:

- **Links.** A resolved inline or reference link writes `<a href="…">`, with ` title="…"` when the title is not empty, and `</a>` ([`html.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/html.c#L384-L400)). [render/link.ts](../../src/render/link.ts) cleans the destination and title as `cmark_clean_url` and `cmark_clean_title` do, then escapes them with `houdini_escape_href` and `escape_html`. An inline link's target is sliced from its source range only when its span is written.
- **Images.** An image writes `<img src="…" alt="…" />`, with ` title="…"` before `/>` when the title is not empty ([`html.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/html.c#L402-L420)). The `alt` text is written as empty; see [known gaps](./known-gaps.md#known-gaps).
- **Autolinks.** An angle autolink is an email link when it has no `:`, and both its `href` and text have entities decoded ([`inlines.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/inlines.c#L154-L183)). A bare `www.` link gets `http://` in its `href`, and a bare URL starts at the scheme letters before its `:` ([`autolink.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/autolink.c#L168-L280)). Email links from the extension's postprocess step are not written.
- **Aligned cells.** Each column's alignment comes from the trimmed delimiter cell ([`table.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/table.c#L382-L392)), and a cell in an aligned column writes `<th align="left">` or `<td align="left">` ([`table.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/extensions/table.c#L798-L814)). For the generated empty cells of a short row, only the first aligned one is written. Its quotes close a double-quoted value and end the tag, and the empty cells after it cannot change the state that follows. Writing every one made a wide table with short rows quadratic: 25 s for the aligned-table scaling test.
- **Definition-only paragraphs.** A paragraph writes `<p>` only when text remains after its reference definitions, or when it becomes a table header. Before, a paragraph of only definitions counted as markup, which ended an open tag that GitHub keeps open (fixture `definition-only-paragraph-keeps-tag`).

**When the markup is written.** In the data state, these writes cannot change the tokenizer state, and only a link's `a` element can change the element stack. So the inline phase holds a link, image, or autolink span only when the tokenizer is outside the data state, when earlier spans are held, or when foreign content makes the `a` element matter. A text block without `<` is lexed only when it has brackets or a bare autolink (`www.` or `://`) and `mayLeaveData()` is true. The block phase writes aligned cells only when `mayLeaveData()` is true, too.

`mayLeaveData()` is true inside a footnote definition, when the tokenizer is outside the data state, or when events are held and a held event can leave the data state. Held events replay in order, so until such an event is held, the state stays as the tokenizer has it now. The flag for that, `heldLeavesData`, starts as the tokenizer's state when holding begins:

- **A held HTML block line** keeps the data state when it has no `<`, or when its only `<` opens a comment that closes on the line, such as `<!-- prettier-ignore -->`. A `--!>` before the last `-->` also closes the comment, and the text after it has no `<`.
- **A held text block with raw HTML** keeps the data state unless it holds `<?`, `<![`, or `--!>`. Other inline raw HTML is a complete tag, comment, or declaration, which the browser ends where cmark-gfm ends it. A processing instruction, and a CDATA section outside foreign content, end at their first `>` in the browser. cmark-gfm's inline comment ([`scanners.re`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/scanners.re#L57)) accepts `--!>` and ends at a later `-->`, but the browser ends the comment at `--!>`. In each case, the text after the browser's end can open a tag. `<!-->` and `<!--->` are not in this class: cmark-gfm ends them at once, as the browser does ([`inlines.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/inlines.c#L940-L949)). The other parse errors inside a comment, such as a nested `<!--` or `--!` before other text, do not end it. Tags whose content the browser does not tokenize as HTML, such as `<textarea>`, are escaped by GitHub's tag filter.

The `held markup meets the state that held raw HTML leaves` test locks each case. The fuzz sets cannot: a mutant that never sets the flag gives no difference on 20,000 documents of `tables`, `rich`, and `links`. For `--!>`, a scratch set that mixes `--!>`, `<a title="`, held references, and aligned cells gave 1, 2, and 1 mismatches on seeds 7, 11, and 23 with 20,000 documents each before the check, and 0 after, on 2026-11-16. It is not a recorded set, because so few documents reach the case.

**Rejected: treat every held HTML line or raw HTML block as leaving the data state.** It is simpler, but rule-list READMEs, such as eslint-plugin-react's, hold a `<sup>` or a marker comment before a large aligned table. Every cell was then held and replayed in the data state, for no effect: eslint-plugin-react's README took 17% longer and the corpus 2.3 to 3.3% longer than `develop`. See [Corpus and performance](./linear-time.md#corpus-and-performance).

**GitHub probes (2026-11-16).** Ten probes sent one synthetic document each to `/markdown` in `gfm` mode. The [probe fixtures](./github-oracle.md#probe-fixtures) hold their documents and outputs; their `evidence` points to this section. Each one fails on `develop` before this change and passes with it.

| Fixture | Finding |
| --- | --- |
| `reference-link-closes-value` | The reference link's `href` quote closes the value, so `<!-- b -->` is a comment |
| `inline-link-closes-value` | An inline link in a block without raw HTML closes the value |
| `image-closes-value`, `image-closes-value-visible` | An image closes the value |
| `www-autolink-closes-value` | A bare autolink closes the value |
| `angle-autolink-closes-value` | An angle autolink closes the value |
| `aligned-header-closes-value` | An aligned header cell closes the value |
| `aligned-column-closes-value` | Only the aligned column's quote closes the value, so the unaligned header stays hidden |
| `definition-only-paragraph`, `definition-only-paragraph-keeps-tag` | A paragraph of only definitions writes nothing, so the open tag reads `<!-- c >` and `HIDE` renders |

The existing fixture `task-attribute-reference`, a resolved reference link in an open attribute value, was a known gap and now passes.

The [link and cell markup tests](../../tests/specs/rendering/link-and-cell-markup.ts) lock these cases, and all 8 fail on `develop` before this change. In scanner copies, writing no generated empty cells fails only the empty-cell test, and lexing no `<`-free block for a bare autolink fails only the autolink test.
