# Reference budget and replay

A reference copies its definition's destination and title into the output, so the renderer caps the bytes that resolved references can add. The scanner models that cap. This file also covers why block events are held and replayed: a reference can use a definition that appears later in the source.

## Reference links need every definition first

`[x][r]`, `[r][]`, and `[r]` are links only when the document defines `r`, and the definition can come after the use. The block phase collects the normalized label of each definition it drops. Block events go straight to the inline and browser phases until a replayed text block contains both `[` and `]`. A replayed block normally needs `<`; when foreign-content tracking is enabled, paragraphs are replayed even without `<` because their generated tags can affect the element stack. A block without `<` is also replayed when its [link or autolink markup](./inline-and-links.md#link-image-and-cell-markup) can meet a state other than data. From that block on, events are buffered and replayed after the block pass with every label known. Each event is a small tagged object. Adjacent lines of one HTML block are combined into one event, which replay splits by line, so a long HTML block holds one event. On 2026-11-16 (Node 26.13.0), this representation replaced packed number arrays with no measurable change: 11.7-12.0 ms against 11.6-12.1 ms on the corpus, and 101-103 MB against 100-102 MB peak RSS for 500,000 HTML block lines after one marker. **Rejected: a block pass that collects definitions first,** run only when the source contains `]:`, which every definition needs. It would remove the buffer, but on 2026-11-14, 91 of the 170 corpus files that contain `<!--` also contained `]:`, which is 55% of their bytes. Each of those would pay for a second full block pass. An earlier version that ran the second pass on every document took about twice as long as base, while the buffer costs about 10%. Labels compare as `normalize_reference` normalizes them: whitespace is trimmed and collapsed with `cmark_isspace`, NUL and lone surrogates become U+FFFD, and case is folded with [the exceptions](./github-oracle.md#reference-label-case-folding) that make JavaScript's case mapping match cmark-gfm's.

## Reference expansion budget

**Decision: model cmark-gfm's reference expansion budget.** Each use of a reference copies its definition's destination and title into the output, so a short document could expand into a huge one. cmark-gfm caps the bytes that resolved references copy in at the document's size or 100,000 bytes, whichever is larger ([setup](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/blocks.c#L652-L659)). A definition's size is the byte length of its cleaned destination and title ([`references.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/references.c#L35)). Each lookup is checked on its own: a reference whose definition does not fit in the remaining budget renders as plain text and consumes nothing, and a later reference to a smaller definition can still resolve ([`map.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/map.c#L95-L100)).

GitHub applies the cap. On 2026-11-14, `/markdown` in `gfm` mode rendered `'[r] '.repeat(n) + 'x <!-- a -->PRESERVE ![<!-- a -->old][r] tail<!-- /a --> KEEP\n\n[r]: '` followed by 1,000 `u` characters as follows. With n = 98, the image resolved, so its alt text held no comment. With n = 101, exactly 100 links resolved, and the image rendered as the text `![old][r]`, with its comments stripped as real comments. The fixtures `budget-98` and `budget-101` in the [probe fixtures](./github-oracle.md#probe-fixtures) hold both outputs. A scanner that resolves every defined reference skips that comment and reports the outer `<!-- a -->` and `<!-- /a -->` as markers, so a consumer that replaces text between them deletes `PRESERVE ![`.

[budget.ts](../../src/budget.ts) models it in two steps:

- **Fast path.** At most one lookup succeeds per `]`. If the number of `]` times twice the largest definition's UTF-8 size cannot exceed the cap, no lookup can fail, and nothing more runs. It measures the source bytes and does not read the entity table. The factor of 2 covers entity decoding, which grows a definition by at most 1 byte per entity, such as `&nGt;` (5 source bytes, 6 decoded bytes). NUL and lone surrogates count as 3 bytes, because cmark-gfm reads them as U+FFFD. Of the 758 files in the corpus sample, only one fails this bound: a 112 KB CHANGELOG with 2,508 `]` and about 1,250 issue references, which does come close to its cap.
- **Slow path.** A second block pass lexes every text block that holds `[` and `]`, including blocks without `<`, because their references use up the budget too. It counts sizes in document order and records each failed lookup by its block and its position among the block's lookups. Replay lexes some of the same blocks with the same text, so the lookups in each block come in the same order, and it treats a recorded failure as undefined. Failures are recorded for every block with brackets, because a link writes markup even in a block without raw HTML. Both passes find brackets with [block/filter.ts](../../src/block/filter.ts), so the two choices cannot drift apart. The cap counts the input bytes before NUL replacement, as cmark-gfm's `total_size` does.

Sizes follow `cmark_clean_url` and `cmark_clean_title`: the destination is trimmed, the title loses its delimiters, numeric entities decode with houdini's 8-digit limit, named entities whose first decoded byte is ASCII decode through cmark-gfm's own table, and backslash escapes are removed, including a backslash that an entity such as `&bsol;` produced. A name that starts outside ASCII keeps its source bytes; see the decision below. Sizes are byte counts in cmark-gfm's encoding. When cmark-gfm decodes a numeric entity for U+FFFE or U+FFFF, its encoder writes 1 byte, but the same characters written literally in the source keep their 3 UTF-8 bytes ([`utf8.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/utf8.c#L202-L207)).

**Decision (2026-11-17): keep only the entity names that decode to ASCII.** [render/entities.ts](../../src/render/entities.ts) holds 49 of the 2,125 names from [`entities.inc`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/entities.inc), the names whose first decoded byte is ASCII, grouped by decoded byte length and that byte. [generate-entities.ts](../../scripts/oracle/generate-entities.ts) keeps those names and fails if the count changes. Its named lookup map is built on first use. The budget needs a name's decoded byte length, and [render/code-block.ts](../../src/render/code-block.ts) keeps the ASCII first character of a named entity value in a fence language, so `&bne;`, `&nvlt;`, and `&nvgt;` keep their first byte and replace the rest with one U+FFFD: `&bne;` becomes `=\uFFFD`. Houdini matches a name of 2 to 31 bytes that ends in `;` ([`houdini_html_u.c`](https://github.com/github/cmark-gfm/blob/0.29.0.gfm.13/src/houdini_html_u.c#L80-L100)). A name that starts outside ASCII is never decoded: its source text is escaped, and no tokenizer state transition compares a non-ASCII character; it is charged its source bytes in the slow path instead, which is the [known gap](./known-gaps.md). The table was 17,943 bytes of the 63,286-byte minified bundle and is 2,065 bytes of the 47,504-byte bundle (2026-11-17, `pnpm size`). [github-oracle.md](./github-oracle.md#entity-table) has the generator and comparison.

The 2026-11-14 rejection of inexact counting used `&amp;` as its evidence: 200 uses counted 1,000 bytes where cmark-gfm counts 200, so the scanner rejected an image that GitHub resolves, and a consumer replacing text between markers would delete text GitHub shows. That evidence does not apply to this table: `&amp;` decodes to one ASCII byte and is still counted exactly, as are the other 48 names. Only a name whose value starts outside ASCII is counted by its source bytes, and no real document confirmed against GitHub needs it. [CONTRIBUTING.md](../../CONTRIBUTING.md#principles) sets that tie-break: exactness that costs significant size or time becomes a recorded gap unless a real document confirmed against GitHub needs it. The oracle fuzz output is byte-identical to develop on every fragment set and seed, so no generated document crosses that boundary where the approximation changes a report, and the suite's budget boundary cases use retained names.

- **Rejected: a full-value table.** The compact generated table is about 17 KB against 37 KB for full decoded values. The tokenizer does not compare non-ASCII characters in fence language attributes.
- **Rejected: keeping the 116 names whose decoded value grows beyond its source length.** Names such as `&nGt;` (5 source bytes, 6 decoded) would keep the slow path from under-counting, but they add about 0.45 KB of names for an input class that no probe, test, or corpus document reaches, and the under-count is covered by the known gap.

**Rejected:**

- **Documenting the cap as a gap.** The failure is a silent wrong edit, and the fast path makes the model free for documents that cannot reach the cap.
- **Buffering every text block with brackets in one pass.** This avoids the second pass, but it costs memory on every document, which two review rounds had just removed.
- **Refusing to update documents that might reach the cap.** It would refuse documents that render fine, such as generated API references that reuse definitions heavily.
